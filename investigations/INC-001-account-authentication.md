## Summary

This investigation was created as part of a controlled Microsoft Entra ID cloud security lab. Multiple failed sign-in attempts were generated against the fictional test account **Alex Morgan** to simulate a potential account authentication attack.

The activity was reviewed in the Microsoft Entra sign-in logs. The failed events returned error code **50126**, which Microsoft defines as an invalid username or password. Microsoft also notes that some 50126 events are expected because users can enter incorrect credentials. 

The repeated failures were intentionally generated for this lab and do not represent a confirmed compromise.

## Observed Activity

Several failed sign-in events were observed for the Alex Morgan test account.

### Example Failed Sign-In

- **Time:** Approximately 2:57:50 PM
- **Status:** Failure
- **Error Code:** 50126
- **Failure Reason:** Error validating credentials due to invalid username or password
- **Authentication Requirement:** Single-factor authentication
- **Authentication Method:** Password
- **Result:** Authentication failed
- **User:** Alex Morgan

Additional failed attempts occurred within the same short period, creating a pattern that would be worth investigating in a production environment.

## Investigation

The sign-in events were reviewed to determine whether the activity represented a legitimate user error or suspicious authentication behavior.

The investigation considered:

1. Number of failed attempts
2. Time between attempts
3. Username involved
4. Authentication method
5. Application being accessed
6. Source IP and location
7. Device and browser information
8. Successful sign-ins surrounding the failures
9. Whether the activity was expected or authorized

The activity was determined to be **controlled test activity** because the failed authentication attempts were intentionally generated as part of the security lab.

## Findings

### Finding 1 — Repeated Failed Authentication

Multiple authentication failures occurred against the same test account within a short period.

**Assessment:** Suspicious pattern that should be investigated in a production environment.

### Finding 2 — Error Code 50126

The failed events returned Microsoft Entra error code **50126**.

**Assessment:** The credentials supplied during the sign-in attempt were invalid.

### Finding 3 — No Evidence of Compromise

The activity was intentionally generated by the lab owner for testing purposes.

**Assessment:** No evidence of an actual account compromise was identified.

## MITRE ATT&CK Mapping

**T1110 — Brute Force**

The activity is mapped to the Brute Force technique because repeated authentication attempts against an account can be associated with credential guessing or password attacks.

**Important:** This mapping represents the behavior being simulated. The lab activity was authorized and did not represent an actual attack.

## Detection Recommendation

A production SOC could create a detection for repeated failed sign-ins against the same account.

Example KQL:

```kusto
SigninLogs
| where TimeGenerated > ago(24h)
| where ResultType == "50126"
| summarize
    FailedAttempts = count(),
    FirstAttempt = min(TimeGenerated),
    LastAttempt = max(TimeGenerated)
    by UserPrincipalName, IPAddress
| where FailedAttempts >= 5
| order by FailedAttempts desc
```

The threshold should be adjusted based on the organization's normal authentication behavior to reduce false positives.

## Recommended Response

If the same pattern occurred in a real environment, the analyst should:

1. Verify whether the user recognizes the activity.
2. Review successful and failed sign-ins surrounding the event.
3. Examine the source IP, location, device, browser, and application.
4. Check whether other accounts show similar activity.
5. Determine whether the account is at risk of compromise.
6. If unauthorized activity is suspected, follow the organization's account containment and credential-reset procedures.
7. Continue monitoring for additional authentication failures.

## Final Assessment

**Disposition: Benign / Authorized Lab Activity**

The repeated authentication failures were intentionally generated to test Microsoft Entra ID monitoring and demonstrate a SOC investigation workflow.

The activity successfully demonstrated how an analyst can identify repeated authentication failures, review sign-in details, determine whether the activity is legitimate, map the behavior to MITRE ATT&CK, and recommend a detection strategy.
